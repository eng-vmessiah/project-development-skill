# G4 — Closure Decisions and Candidate Bounds

**Status:** `local_verified_live_auth_open`
**Scope:** local/fake/injected implementation verified; live Hermes mechanism remains open
**Implementation authorization:** local repository only, as bounded by `EXECUTION-AUTHORIZATION.md`
**External effects:** disabled

This packet separates candidate defaults from approved policy. Local fixtures implement and verify the bounded policy, but no value below claims that the current Hermes Gateway supports the proposed seam or authorizes live activation.

## 1. Authentication seam options

| Option | Description | Strengths | Risks/unknowns | Recommendation |
|---|---|---|---|---|
| A — existing session credential + activation artifact | reuse the authenticated Gateway transport and add a Gateway-issued one-use activation bound to the observer/owner/profile/workspace | smallest new surface; keeps auth Hermes-owned | existing credential modes differ by transport; Fleet binding is not yet supported | candidate fallback |
| B — Gateway-issued one-use activation ticket | authenticated Gateway issues a short-lived, single-use ticket; Fleet presents it with an observer identity and explicit binding | clear anti-replay boundary; explicit association; fail-closed on reuse | ticket issuance and verification API do not exist yet; key/rotation design required | **recommended design direction** |
| C — process credential / local trust | Fleet uses a local process credential to access Gateway | useful only for an isolated fixture | weak as a general identity; unsuitable for shared/global Fleet; must not become implicit production trust | fixture-only candidate |

The design direction is locally represented and tested only with fake/injected Gateway behavior. The live Hermes mechanism is still open: Gateway owner/security review must define and implement issuance, binding, atomic consume/revoke, transport authentication, storage, rotation, and operational rollback before live use. Local implementation does not authorize or imply that mechanism.

## 2. Candidate activation bounds

These are review candidates, not approved production values:

| Bound | Candidate | Rationale |
|---|---:|---|
| activation ticket TTL | 5 minutes | short handoff window; one-use |
| activation nonce | 128 bits minimum | replay resistance; generated by Gateway |
| association idle TTL | 90 seconds after missed heartbeat | bounded stale detection |
| heartbeat interval | 30 seconds | three observations within candidate stale window |
| cursor TTL | 15 minutes | limits replay artifact lifetime |
| reconnect grace | 60 seconds | permits transient local transport loss |
| event payload | 4 KiB maximum | metadata-only bounded payload |
| envelope | 8 KiB maximum | prevents oversized wrapper/provenance |
| replay batch | 100 events maximum | bounded memory and delivery work |

These values require owner/security review and clock-skew policy. They MUST NOT be embedded in runtime until approved.

## 3. Cursor and activation integrity

Recommended design:

- Hermes Gateway is the only issuer of activation artifacts, stream boundaries, epochs, and cursors.
- The serialized representation is opaque to Fleet application code.
- Verification MUST cover schema/version, issuer, association, subscriber, owner/profile/workspace binding, epoch, expiry, nonce/consumption state, and purpose.
- Fleet MUST NOT mint, edit, extend, or transfer a Gateway artifact.
- A consumed nonce is retained as a bounded replay tombstone for at least the artifact's active lifetime plus the approved clock-skew window.
- Key/token rotation and revocation remain Hermes Gateway/security decisions.

If verification cannot be performed, return `activation_invalid` or `invalid_provenance`; never fall back to unsigned local trust.

## 4. Redaction and allowlist

The initial v1 observer payload is allowlist-only:

```text
session_ref
association_ref
ownership_mode
runtime_surface enum
status enum
reason_code enum
heartbeat_sequence
observed_at
metadata_version
stream_epoch
sequence
bounded opaque provenance references
```

The following are deny-by-default even if a source event contains them:

```text
prompt
history
message content
tool name/arguments/results
provider/model response
approval content
credentials/tokens/keys
filesystem paths
terminal frames
environment variables
network addresses beyond approved opaque refs
```

Unknown fields and unknown enum values fail closed. Redaction occurs before persistence, translation, replay, audit, or external delivery.

## 5. Cursor acknowledgement and durability

Recommended ordering:

```text
receive
→ validate envelope and binding
→ redact/normalize
→ persist bounded event + durable delivery outbox item
→ atomically advance ingestion cursor and outbox pending state
→ deliver from outbox with idempotent delivery key
→ mark delivery outcome/observer acknowledgement
```

The ingestion cursor represents durable acceptance by the bridge, not proof of observer delivery. A persisted outbox item that is not delivered MUST remain recoverable and redeliverable after restart. Observer delivery is at-least-once and MUST use the idempotency key so a retry cannot duplicate state mutation.

If event persistence, ingestion cursor, and outbox pending state cannot be committed atomically, the bridge MUST prefer duplicate replay over loss and MUST NOT advance the cursor optimistically.

The idempotency key is:

```text
(association_ref, stream_epoch, sequence, event_id)
```

Conflicts are `invalid_provenance` and require resync.

## 6. Failure and recovery policy

- Auth/issuer failure: fail closed; no session-existence disclosure.
- Expired activation/cursor: require explicit renewal/resubscribe.
- Replayed activation: reject; do not create a second association.
- Missed heartbeat: transition to `reconnecting`, then `stale` after the approved bound.
- Unknown epoch or retention gap: `cursor_stale`/`replay_gap`; require snapshot/resync.
- Redaction or schema failure: reject/quarantine; never forward raw data.
- Restart without continuity proof: new epoch or stale/orphaned association; never fabricate history.
